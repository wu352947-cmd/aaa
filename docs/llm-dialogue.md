# 台词 AI 设计：让对话多变，又不让数字和历史出错

## 要解决的问题

NPC 如果每次都说同样的话，很快就会单调；可如果把对话完全交给大模型，又会遇到三个风险：

1. **编数字**：模型随口说出一个价格或仓位，玩家照着下单，游戏就“骗”了玩家。
2. **穿越**：1995 年的上海交易员说出“微信”“量化”，或者提前说出当晚“交易无效”。
3. **破坏确定性**：同一个种子、同一串操作必须算出同一局（每日挑战、排行榜校验、录像回放都靠它），而模型的输出每次都不一样。

## 核心原则：引擎决定说什么，模型只决定怎么说

```
玩家点“试探高振宇”
        │
        ▼
┌──────────────────────────────┐
│ 引擎（确定性，带种子）          │  决定：他今晚说真话还是谎话、透露什么、什么语气、
│ scenario.social()             │  关系值怎么变、是否获得情报……全部写进存档与动作日志
└──────────────┬───────────────┘
               │ 意图包 DialogueIntent（不含任何秘密）
               ▼
┌──────────────────────────────┐
│ 台词层（非确定性，可选）          │  模板 或 OpenAI 兼容模型（DeepSeek、OpenCode Go……）
│ llm/director.ts               │  把意图包写成一句符合人物与年代的话
└──────────────┬───────────────┘
               │ 候选台词
               ▼
┌──────────────────────────────┐
│ 校验器（确定性）                 │  数字 / 时代错置 / 未来知识 / 第四面墙 / 长度
│ llm/validate.ts               │  不合格 → 带着理由让模型重写一次 → 仍不合格 → 模板
└──────────────┬───────────────┘
               ▼
          显示给玩家（不写回游戏状态）
```

### 1. 投资逻辑由引擎保证，不靠模型“懂金融”

- NPC 的每一个决定都在引擎里用公式算出来。例如辽北发展是否倒戈：`诱惑 = 消息可信度 − (关系 × 0.5 + 违约金 × 0.35 + 共享研究 × 0.1)`，超过阈值才倒戈。玩家通过送研究纪要、加违约金、告发，真的能改变这个结果（有测试覆盖）。
- NPC 是否撒谎也由引擎决定：`说真话的概率 = 0.15 + 0.5 × 关系值`。撒谎时，**意图包里只有谎话本身**，模型根本不知道真相，所以无论玩家怎么套话，模型都泄露不了。
- 玩家看到的“线索”同样来自引擎：逐笔成交里的席位号、传呼不回、对方语气躲闪。台词只是把这些线索说得更像人话。

### 2. 历史真实感靠“年代风格包”加硬校验

`llm/era.ts` 为每个剧本维护一份风格包：

| 字段 | 作用 | 1995 上海示例 |
| --- | --- | --- |
| `lexicon` | 写进提示词，鼓励使用的当年说法 | 红马甲、大户室、传呼机、大哥大、保值贴补、侬、阿拉 |
| `anachronisms` | 出现即判不合格 | 手机、微信、互联网、量化、私募、T+1、融券 |
| `foreknowledge` | 角色此刻不可能知道的事，出现即判不合格 | 交易无效、327 事件、暂停国债期货、1056（万口） |
| `safeNumbers` | 允许出现的固定数字 | 1995、327、132 |

每个人物还有一张人设卡（口音、口头禅、性格），写在 `scenarios/s327/data.ts` 的 `persona` 字段。人设卡里不放秘密目标。

### 3. 数字由校验器拦截，不信任模型自觉

- 台词里的每个阿拉伯数字，都必须出现在意图包的 `numbers` 列表（引擎给的）或风格包的 `safeNumbers` 里（容差 0.2%），否则判为“编造了数字”。
- 不带数字的意图包，台词里也不能出现“三千万”“一百五”这类中文大数。
- 10 以内的整数放行（“两句”“三天”这类口语）。

### 4. 确定性：台词完全不进入模拟

- 台词不写回 `Game` 状态，也不进入动作日志；重放、排行榜校验只看动作日志，所以模型输出每次都不同也无所谓。
- 闲聊（自由输入）不消耗精力、不改变任何数值。模型拿到的只有该 NPC 此刻的“对外口径”，所以玩家再怎么套话都套不出东西，也不会因为话术不同而得到不同的数值结果。
- 模型调用失败、超时或校验不过，一律退回模板台词，游戏照常进行。

## 接入方式

- 游戏内 **设置 → 台词 AI**：填写接口地址、API Key、模型名，点“测试连接”。
  - DeepSeek：地址 `https://api.deepseek.com`，模型 `deepseek-chat`。
  - OpenCode Go 或其他 OpenAI 兼容服务：填它们的 `/v1` 地址与模型名即可（会自动补 `/chat/completions`）。
- 浏览器跨域被拦时：在项目根目录建 `.env.local`，写入 `LLM_PROXY_TARGET=https://api.deepseek.com`，重启 `npm run dev`，把接口地址改成 `/llm`，由 Vite 开发服务器转发。
- API Key 只存在本机浏览器的 localStorage，适合本地开发与个人游玩。正式上线时应改为服务端代理（设计文档第十四章的无状态 API），不要把 Key 下发到客户端。

## 成本控制

- 只有社交动作和闲聊才调用模型，行情推进从不调用。白天和夜晚各有 3 点精力（每次社交动作花 1 点），每个 NPC 每天最多 4 句闲聊。
- 同一意图包的结果会缓存，重复试探不会重复计费。
- 每句台词上限 160 token，失败最多重试一次。

## 以后可以加强的地方

- 为每个剧本积累一批经人工审校的“范例台词”，作为 few-shot 示例放进提示词，进一步统一口吻。
- 把校验器扩展为“事实一致性”检查：让台词里提到的人名、机构名也只能来自意图包。
- 把被拦下的台词记进本地日志，定期人工复查，反过来补充 `anachronisms` 与 `foreknowledge` 列表。
